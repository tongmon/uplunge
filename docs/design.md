## 1. 한 줄 소개

물이 새는 탑을 제트팩 기사가 **아래로 쏘며 위로** 올라가는 로그라이크 플랫포머.
"아래로 쏘면 위로 오른다. 물이 차오르기 전에, 꼭대기의 공주에게."

- 영감: Downwell(하강 로그라이크)을 위아래로 뒤집은 구조
- 카메라, 물리, 손맛 기준: Celeste
- 무기 다양성: Jetpack Joyride
- 아트 방향: Shelldiver

## 2. 디자인 원칙 ✅

1. **Downwell 수준의 단순한 조작**: 좌우 이동과 버튼 1개.
2. **실수의 대가는 높이가 아니라 HP**: 떨어져도 진행이 사라지지 않음.
3. **무기 = 이동 방식**: 반동이 곧 추진력.
4. **목표가 한눈에 보임**: 아래에서 물이 차오르고, 꼭대기가 목적지.
5. **카피처럼 보이지 않기**: 시스템을 이 게임만의 동사(추진, 드릴, 물, 구조)에 묶음.

## 3. 조작 ✅

| 입력 | 지상 | 공중 |
|---|---|---|
| 좌/우 | 이동 | 공중 이동 |
| 버튼 (점프/발사) | 점프 | 누르고 있으면 아래로 발사 → 위로 추진 |

- 점프 직후 첫 발사는 버튼을 한 번 뗐다가 다시 눌러야 함 (Downwell 방식, 점프와 발사가 섞이지 않게).
- 모바일: 화면 아래 남는 영역에 좌/우 버튼과 액션 버튼 배치 (7장 참고).

## 4. 핵심 루프 ✅

```
위의 적·장애물을 옆으로 피하며 접근 → 추월
  → 아래에 둔 적을 쏘거나(= 추진) 떨어지며 밟기(= 연료 충전 + 큰 바운스)
  → 발판 없이 적만 밟으며 계속 올라가면 콤보
  → 발판에 착지하면 쉴 수 있지만 콤보는 끝남, 물은 계속 차오름
```

**핵심 튜닝 비율 🧪**: (탄창 하나로 오르는 높이) ÷ (적 사이 평균 세로 간격)

- 1보다 크면 적만 밟으며 연쇄 상승 가능
- 1보다 작으면 발판을 밟아야 함
- 구역별 난이도를 이 비율로 조절

## 5. 시스템

### 5.1 건제트 (추진) ✅

- 공중에서 발사하면 `vy = min(vy, -thrust)` 적용.
  - Downwell의 반동 공식, Celeste의 가변 점프와 같은 "속도 상한" 패턴이라 속도가 폭주하지 않음.
- 탄약 = 연료. 시간이 지나도 회복되지 않음.
- 연료 전량 충전 조건:
  - 발판 착지
  - 적 밟기
  - 피격 (물 접촉 포함)
- 연료가 0일 때는 발사 버튼을 눌러도 아무 효과가 없음.
  - 업그레이드로 "연료 0일 때 홀드하면 낙하 감속" 같은 효과를 추가 가능.
- 시작 가설 🧪:
  - 탄창 8발, 발사 간격 0.1초, thrust 240px/s
  - 이 값이면 탄창 하나로 약 8~9타일 상승

### 5.2 밟기와 적 ✅

- 위에서 밟으면 다음이 한 번에 일어남:
  - 처치 + 연료 전량 충전 + 콤보 +1
  - **점프보다 높은 바운스**
- 바운스 가설 🧪: Celeste 퍼퍼(Puffer) 밟기처럼 위쪽 속도를 0.2초 동안 유지.

**적 3분류**: 위험한 면은 가시 모양 + 색으로 일관되게 표시

| 분류 | 처치 방법 | 예시 역할 |
|---|---|---|
| 위가 안전 | 밟기 | 기본 발판 역할 적 |
| 아래가 안전 | 드릴 헬멧으로 들이받기 | 머리 위를 막는 적 |
| 전부 위험 | 쏘기만 가능 | 추월한 뒤 아래로 쏴서 처리 |

- **퍼퍼형 적**: 옆이나 아래에서 닿으면 피해 대신 옆으로 튕겨 보냄. 피하는 동작이 곧 이동 수단이 됨.

### 5.3 콤보 ✅

- 발판에 착지하면 종료. 피격으로는 끊기지 않음.
- 보상 단계는 Downwell(8/15/25)을 참고하되 수치와 보상은 새로 설계 🧪.
  - 후보: 젬, 최대 연료 +1, HP 조각, 수위 하강

### 5.4 물 (차오르는 위협) ✅

Celeste RisingLava의 따라잡기(고무줄) 로직을 사용합니다. 아래 수치는 8px 타일 기준인 Celeste 값을 2배로 환산한 것입니다 🧪.

- 기준선: 카메라 아래 끝에서 24px 위
- 기본 속도: 60px/s
- 기준선보다 아래로 뒤처지면 속도가 최대 2배까지 오름. 기준선에서 192px 이상은 멀어지지 않음.
- 화면 안으로 올라오면 64px 구간에 걸쳐 속도가 최대 0.5배까지 내려감.
- 그래서 잘하는 플레이어는 거의 의식하지 않고, 머뭇거리는 플레이어만 압박을 받음.

**추락 안전망** ✅ (Celeste 어시스트 모드의 무적 용암 처리 + HP)

물에 닿으면:
- HP -1
- 연료 전량 충전
- 위로 크게 튕겨 냄
- 물이 0.4초 동안 96px 내려간 뒤 0.5초 멈춤
- 짧은 무적 시간

### 5.5 지형 ✅

| 블록 | 동작 |
|---|---|
| 단방향 발판 | 아래에서 통과, 위에 착지 |
| 드릴 블록 | 드릴 헬멧으로 속도와 상관없이 파괴. 깰 때 0.05초 멈춤 + 작은 위쪽 튕김 |
| 파괴 불가 블록 | 경로 설계용 |

필수 보정 (Celeste 방식):
- 천장 모서리에 머리를 부딪히면 옆으로 1~4px 밀어서 통과시켜 줌
- 단방향 발판을 통과하는 중이면 위로 밀어 주는 보조 속도

### 5.6 무기와 슈트 ✅ (두 층 구조)

**무기**: 영구적이고 교체식. 반동 = 추진 방식. 목록은 후보 🔶

| 무기 | 추진 특성 | 전투 특성 |
|---|---|---|
| 리벳건 (기본) | 연사, 꾸준히 떠오르는 호버 | 단발, 빠른 연사 |
| 블런더버스 | 한 방에 크게 상승 (사실상 더블 점프) | 근거리 산탄 |
| 증기 캐논 | 누르고 있다 떼면 모은 만큼 수직 발사 | 관통 |
| 펌프건 | 수면 가까이에서 추진력 증가 | 물줄기 |

- 무기를 바꿀 때 HP +1 또는 최대 연료 +2 중 하나를 받는 맞교환 (Downwell 구조 유지).

**슈트**: 일시적이며 맞으면 대신 부서지는 1회 방패 (Jetpack Joyride 탈것 방식). 목록은 후보 🔶

- 버튼 하나가 하는 일 자체를 바꿈.
- 지속 시간이 끝나기 0.5초 전부터 깜빡이며 경고 (Celeste 깃털 방식).

| 슈트 | 버튼 동작 |
|---|---|
| 날개 슈트 | 누를 때마다 날갯짓 |
| 중력 반전 슈트 | 위로 "떨어짐" (Downwell에 대한 오마주) |
| 스프링 부츠 | 누르는 시간만큼 모았다가 점프 |

### 5.7 업그레이드 ✅ (방향), 🔶 (목록)

Downwell은 23종, 전부 1회 획득, 균등 확률 추첨, 조합 효과 로직 없음. 우리는 이렇게 차별화합니다.

- 테마 동사(추진, 드릴, 물, 구조, 밟기)에 묶기
- 맞교환형 업그레이드 포함
- 같은 태그 3개를 모으면 세트 효과
- 물을 조작하는 업그레이드 (상승형에만 있는 축)

| 후보 | 효과 |
|---|---|
| 유령 갑옷 | 처치 시 다음 1회는 적을 통과 |
| 드릴 회수기 | 블록을 깨면 연료 1 회복 |
| 부력 조끼 | 층마다 1회, 물에 빠져도 피해 없이 튕겨 나옴 |
| 역류 밸브 | 일정 콤보를 달성하면 수위 하강 |
| 무거운 갑주 | 최대 HP +2, 중력 +15% |
| 스프링 무릎 | 밟기 바운스 +30%, 대신 발판 착지로는 연료 충전 안 됨 |
| 낙하 축전 | 떨어진 거리만큼 다음 추진 1발 강화 |

### 5.8 탑 구조: 갈림길, 격벽실, 구조 NPC, 밸브 ✅

**갈림길** (Hades의 문 아이콘에서 착안)
- 통로가 2갈래로 갈라지고, 각 끝의 보상 아이콘이 위로 미리 보임.
- 위험한 쪽일수록 보상이 좋음.

**격벽실** (Downwell의 시간 정지 방을 대체)
- 들어가면 문이 닫히고 물이 멈춤.
- 구조한 NPC가 여기서 상점이나 대장장이 역할을 함.

**구조 NPC**
- 물에 갇힌 탑 주민. 우회해서 구하면 그 판의 다음 격벽실에 등장함.
- 판이 끝나면 초기화.

**배수 밸브**
- 갈림길 보상 중 하나. 드릴로 부수면 물을 화면 밖으로 크게 밀어내고 몇 초간 멈춤.
- 즉 시간을 버는 장치. 고무줄 로직 때문에 물은 이후 다시 따라옴.

### 5.9 메타 진행 🔶

**판마다 초기화 + 수평 해금** (Downwell 방식)
- 강해지는 영구 성장은 없음.
- 누적 기록(구조한 NPC 수, 도달 높이, 젬 등)으로 새 무기, 슈트, 업그레이드를 **추첨 대상에 추가**.
- 시작 스타일과 팔레트도 해금 대상.
- 저장 데이터는 해금 플래그와 누적 카운터뿐.

## 6. 카메라, 물리, 연출 (Celeste 기준) ✅

**단위**: 초 단위 상수 + 60Hz 고정 업데이트. 위치는 정수 픽셀로 두고 소수점 이하는 따로 누적.

**물리 시작값 🧪**
- 화면에 보이는 세로 타일 수가 Celeste와 같음 (22.5타일). 그래서 8px 타일 기준인 Celeste 값을 16px 타일에 맞게 2배로 환산.
- 현재 값은 [data/tuning.json](../data/tuning.json)에 있음. 아래 표와 함께 고칠 것.
- 물리 동작:

| 항목 | 값 |
|---|---|
| 중력 | 1800px/s² |
| 최대 낙하 속도 | 320px/s |
| 점프 | -210px/s를 버튼을 누르는 동안 최대 0.2초 (발사 프레임 포함 12스텝) 유지 (가변 점프). 끝까지 누르면 52px (약 3.25타일, 꼭대기 중력 절반 없이 측정) |
| 꼭대기 중력 절반 | 세로 속도 절댓값 80 미만이고 버튼을 누르고 있을 때 (M1에서 구현) |
| 좌우 최대 속도 / 가속 | 180px/s / 2000px/s² (2026-10-10 추가, Celeste 값 2배) |
| 공중 가속 배율 | 0.65 (2026-10-10 추가, Celeste 값) |
| 판정 박스 | 12×20px (임시. 캐릭터 약 20px 기준, M1 끝에 🎮 결정) |

- 입력 관대함:

| 항목 | 값 |
|---|---|
| 코요테 타임 (발판에서 떨어진 뒤에도 점프 허용) | 0.1초 (M1에서 구현) |
| 입력 버퍼 (버튼 입력 기억) | 0.08초 (M1에서 구현) |

**카메라**
- 가로는 고정. 세로는 위로만 움직임.
- 플레이어를 화면 아래쪽 약 1/3에 둠.
- 위로 움직일 때 속도 × 0.2만큼 앞을 미리 보여 줌 (Celeste 깃털 상태 방식).
- 따라가는 공식: `cam += (target - cam) * (1 - 0.01^dt)`

**연출**

| 이벤트 | 연출 |
|---|---|
| 밟기, 드릴, 연료 충전 | 0.05초 멈춤 |
| 큰 발사 (스프링, 슈트) | 0.1초 멈춤 + 잔상 |
| 발사 | 발사 방향으로 화면 흔들림 0.2초 |
| 점프 / 착지 | 늘어남·찌그러짐 (0.6, 1.4) / 최대 (1.6, 0.4) |
| 남은 연료 | 제트팩 불꽃이나 헬멧 램프 색으로 표시, 충전 시 흰색 번쩍 (Celeste 머리카락 색 방식) |

## 7. 화면과 레벨 생성

**논리 해상도 🔶: 208×360** (16px 타일, 가로 13칸 = 안쪽 11칸 + 양쪽 벽)
- 맵 모양과 보이는 범위가 모든 기기에서 같도록 폭과 높이를 모두 고정.
- 이 게임은 위가 더 많이 보이면 유리하기 때문에 높이도 고정해야 공정함.
- 플랫폼별 배치:
  - PC 1080p: 3배 (624×1080)를 가운데 배치하고, 양옆은 HUD와 아트 영역. 720p, 1440p, 4K는 각각 2배, 4배, 6배로 정수 배율.
  - 모바일 (가로 1080): 5배 (1040×1800). 남는 세로 공간은 위쪽 HUD와 아래쪽 터치 버튼.

**좁아 보이는 문제**는 화면 폭이 아니라 안쪽 지형으로 해결: 좁은 통로, 넓은 홀, 갈림길 조각.

**레벨 생성**
- 손으로 만든 조각(청크)을 이어 붙임 (Downwell 방식).
- 조각은 좌우 반전 허용, 같은 조각 연속 금지.
- Downwell은 경로 검증 코드가 없음 (어디서든 떨어지면 내려가니까). 상승형은 **도달 가능성 검증이 필수** ✅.
  - 규칙: "연료가 0이어도 점프 높이 안에 발판이 있다" 또는 "연료원이 보장된다".

**조각 작성 규칙** ✅ (2026-10-10 확정, M2에서 조각 생성기를 만들 때 다시 검토)
- LDtk 프로젝트 하나([assets/chunks/chunks.ldtk](../assets/chunks/chunks.ldtk))에 레벨 하나 = 조각 하나.
- 충돌은 IntGrid 레이어 `Collision`: 0 = 빈칸, 1 = solid. 단방향 발판과 드릴 블록 값은 M1에서 추가.
- 조각 폭은 양쪽 벽을 포함해 13칸 (16px 타일), 높이는 자유.
- 레벨을 별도 파일로 저장하는 옵션(Save levels to separate files), 여러 월드(Multi-worlds), `Collision` 레이어의 픽셀 오프셋은 쓰지 않음. 로더가 오류로 거부함.

## 8. 아트 디렉션 (초안) 🔶

참고작 Shelldiver에서 **원칙만** 가져옵니다. 에셋, 캐릭터, 형태를 모방하지 않습니다.

- **크기**: 16px 타일. 캐릭터는 약 20px, 머리(드릴 헬멧)가 큰 2등신.
- **외곽선**: 두꺼운 1px 어두운 외곽선으로 실루엣을 확보.
- **색 구조**: 구역마다 한 색상 계열로 거의 단색 환경 + 캐릭터, 적, 아이템은 채도 높은 대비색.
- **지형**: 어두운 내부 덩어리 + 위쪽 테두리에 밝은 테두리(이끼, 녹, 물때). 계단식 블록 실루엣.
- **배경**: 2~3겹의 시차 스크롤(패럴랙스) 레이어. 멀수록 밝고 채도가 낮음.
- **물**: 모든 구역에서 쓰지 않는 **물 전용 색 1개**를 예약. 밝은 수면선을 그리고, 물에 잠겼을 때는 화면 왜곡 셰이더.
- **효과**: 물방울, 거품, 반짝임, 부드러운 발광. 물결과 흔들림은 셰이더로.
- **진행감**: 위로 갈수록 밝아짐.
  - 어두운 지하 저수조 → 하인 구역 → 서고 → 꼭대기 공주의 방(따뜻한 빛)
- 확정되면 별도의 `art-style.md`(팔레트 hex 값, 외곽선·명암 규칙, 크기표)로 분리.

## 9. 기술

### 9.1 엔진 ✅: Ebitengine (Go) — 2026-10-10 확정

선정 기준은 Claude가 코드를 작성하고 스스로 검증하기 좋은지 여부입니다.

- **프로젝트 전체가 코드와 텍스트**: 에디터 전용 연결 작업이나 바이너리 씬 파일이 없음.
- **Go**: gofmt로 스타일이 하나로 고정되고, 언어가 작고, 정적 타입. 컴파일이 빨라서 수정 → 확인 반복이 짧음.
- **API 안정성**: v2 API가 안정적이라 학습 데이터와 실제 API가 어긋날 위험이 낮음.
- **플랫폼**:
  - Steam: go-steamworks
  - 모바일: ebitenmobile
  - Nintendo Switch: 공식 지원. 단, 닌텐도 개발자 계약과 비공개 툴체인이 필요.
- **단점**: 에디터가 없음. 레벨은 LDtk, 스프라이트는 Aseprite로 보완. UI와 파티클은 직접 구현.
- **대안**:
  - MonoGame/FNA (C#, Celeste가 쓴 스택): 콘솔 포팅 경로가 가장 넓음.
  - Godot 4: 에디터가 필요할 때.

### 9.2 테스트 전략 🔶

1. 게임 로직(물리, 충돌, 생성기)은 렌더링과 분리된 순수 Go 패키지로 작성 → `go test`
2. **입력 리플레이 테스트**: 프레임별 입력을 기록하고 재생해서 결과 위치나 상태를 정해 둔 정답과 비교
3. **조각 도달성 검증**: 모든 LDtk 조각을 `go test`로 자동 검사
4. **스크린샷 자동화**: 디버그 실행 옵션으로 지정한 프레임 PNG를 저장하고 자동 종료 → Claude가 이미지를 직접 확인

### 9.3 에셋 파이프라인 🔶

```
콘셉트 아트 (AI 이미지 생성, Codex CLI)
  → 픽셀 정규화 스크립트 (결정적 도구: 격자 맞춤, 팔레트 양자화, 외곽선 규칙)
  → Aseprite 정리 (Claude가 Lua 스크립트로 수정하고, 사람이 검수)
  → Aseprite CLI 내보내기 (스프라이트 시트 PNG + JSON. 애니메이션 이름은 태그, 판정 박스는 슬라이스)
  → 게임 임포트
```

- 정규화는 LLM이 아니라 **스크립트**로: 같은 입력이면 같은 결과가 나와야 조정할 수 있음.
- **캐릭터 애니메이션**:
  - 파츠(헬멧, 몸통, 팔, 다리, 제트팩)를 레이어로 분리하고, 레이어 위치를 옮겨 프레임을 만들어 일관성 확보.
  - 늘어남·찌그러짐, 흔들림, 불꽃 같은 움직임은 코드로 처리.
- 3D 모델을 픽셀로 렌더링하는 방식은 채택하지 않음. 이 정도 캐릭터 크기에서는 뭉개지고, 파이프라인 비용이 큼.
- Steam 출시 시 AI 생성 콘텐츠 사용 여부를 공개해야 함.
