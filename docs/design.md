## 1. 한 줄 소개

물이 새는 탑을 제트팩 기사가 **아래로 쏘며 위로** 올라가는 로그라이크 플랫포머.
"아래로 쏘면 위로 오른다. 물이 차오르기 전에, 꼭대기의 공주에게."

- 영감: Downwell(하강 로그라이크)을 위아래로 뒤집은 구조
- 카메라, 물리, 손맛 기준: Celeste
- 무기 다양성: Jetpack Joyride
- 아트 방향: Shelldiver

## 2. 디자인 원칙 ✅

1. **Downwell 수준의 단순한 조작**: 좌우 이동과 버튼 1개.
2. **실수의 대가는 높이가 아니라 HP**: 떨어져도 진행이 사라지지 않음.
3. **무기 = 이동 방식**: 반동이 곧 추진력.
4. **목표가 한눈에 보임**: 아래에서 물이 차오르고, 꼭대기가 목적지.
5. **카피처럼 보이지 않기**: 시스템을 이 게임만의 동사(추진, 드릴, 물, 구조)에 묶음.

## 3. 조작 ✅

| 입력 | 지상 | 공중 |
|---|---|---|
| 좌/우 | 이동 | 공중 이동 |
| 버튼 (점프/발사) | 점프 | 누르고 있으면 아래로 발사 → 위로 추진 |

- 점프 직후 첫 발사는 버튼을 한 번 뗐다가 다시 눌러야 함 (Downwell 방식, 점프와 발사가 섞이지 않게).
- 입력 버퍼와 발사 ✅ (2026-10-10): 공중에서 누른 입력이 발사되면 그걸로 소비됨. 연료가 0이거나 발사 간격 대기 중이라 아무 효과가 없던 입력만 점프 입력으로 기억함 (6장 입력 버퍼).
- 모바일: 화면 아래 남는 영역에 좌/우 버튼과 액션 버튼 배치 (7장 참고).

## 4. 핵심 루프 ✅

```
위의 적·장애물을 옆으로 피하며 접근 → 추월
  → 아래에 둔 적을 쏘거나(= 추진) 떨어지며 밟기(= 연료 충전 + 큰 바운스)
  → 발판 없이 적만 밟으며 계속 올라가면 콤보
  → 발판에 착지하면 쉴 수 있지만 콤보는 끝남, 물은 계속 차오름
```

**핵심 튜닝 비율** ✅ (2026-10-11 M1 플레이테스트로 재정의): (닿는 높이) ÷ (적 사이 평균 세로 간격)

- **닿는 높이** = 출발 동작 + 탄창 하나. 출발 동작은 발판이면 점프, 적이면 밟기 튕김.
  - 현재 수치에서 측정: 바닥 출발 187px (점프 53 + 탄창 134), 밟은 뒤 출발 210px (탄창만으로는 134px). `sim.GroundReach`, `sim.StompReach`.
  - 가장 높이 가려면 출발 동작의 꼭대기에서 쏘기 시작해야 함. 발사는 위쪽 속도를 240으로 맞추기만 하므로, 빠르게 오르는 중에 쏘면 출발 동작의 속도를 버림.
  - 처음 정의(탄창 높이만 ÷ 간격)로는 비율 0.74(간격 180)에서도 적만 밟고 오를 수 있어서, 출발 동작을 넣어 다시 정의함.
- 이 비율은 **평균 간격 기준의 지표**. 평균이 1보다 커도 간격 하나가 닿는 높이보다 크면 그 구간은 못 건넘. 간격마다(윗면 기준) 닿는지는 M2의 도달 가능성 검증 도구가 판정함.
- 1보다 크면 적만 밟으며 연쇄 상승 가능, 1에 가까울수록 어려움, 1보다 작으면 발판을 밟아야 함.
- 간격이 좁아도 어려움: 밟기 튕김(약 78px)이 위의 적까지 데려가 부딪힘. 간격이 튕김 높이보다 충분히 크거나, 위 적이 옆으로 비켜 있어야 함.
- 그래서 난이도는 간격에 비례하지 않음. 좁으면 부딪혀서, 넓으면 닿지 않아서 어렵고, 그 사이가 가장 여유로움.

**구역 난이도의 1차 기준** ✅ (2026-10-11, 실험 통로 플레이 결과. M2 조각 생성기와 구역 난이도에 씀)

| 적 간격 | 비율 (바닥 / 밟기) | 체감 | 쓰임 |
|---|---|---|---|
| 64 | 2.9 / 3.3 | 밟기는 쉽지만 튕기다 위 적에 부딪힘 | 피하기 위주 고난도 |
| 96 | 1.9 / 2.2 | 최적, 촘촘해서 판단이 필요 | 중상급 |
| 140~160 | 1.3~1.2 / 1.5~1.3 | 널널함, 피하면서 다음 적을 준비할 여유 | 쉬움 (초반 구역) |
| 180 | 1.04 / 1.17 | 바닥 출발이 빠듯함, 한 번 밟으면 이어짐 | 고수용 |
| 192 이상 | 0.97 / 1.09 | 바닥에서 첫 적에 거의 닿지 못함 | 쓰지 않음 (발판 필요) |

- 실험 통로에서 간격은 적 중심 사이 거리. 밟으려면 발이 적 윗면(중심 + 6px) 위까지 가야 하므로, 바닥 출발 기준으로는 간격 + 6px이 필요함.

## 5. 시스템

### 5.1 건제트 (추진) ✅

- 공중에서 발사하면 `vy = min(vy, -thrust)` 적용.
  - Downwell의 반동 공식, Celeste의 가변 점프와 같은 "속도 상한" 패턴이라 속도가 폭주하지 않음.
- 탄약 = 연료. 시간이 지나도 회복되지 않음.
- 연료 전량 충전 조건:
  - 발판 착지
  - 적 밟기
  - 피격 (물 접촉 포함)
- 연료가 0일 때는 발사 버튼을 눌러도 아무 효과가 없음.
  - 업그레이드로 "연료 0일 때 홀드하면 낙하 감속" 같은 효과를 추가 가능.
- 시작 가설 🧪:
  - 탄창 8발, 발사 간격 0.1초, thrust 240px/s
  - 측정: 공중에서 정지 상태로 탄창 하나를 다 쏘면 134px (약 8.4타일) 상승. 꼭대기 중력 절반이 없으면 133px (`TestMagazineRise`, 2026-10-10)
- 발사 규칙 (M1 구현, 2026-10-10):
  - 공중에서 점프가 아닌 누름이 발사를 시작하고, 버튼을 누르고 있는 동안 발사 간격마다 연사.
  - 땅에 서면 연사가 끝남. 버튼을 누른 채 착지한 뒤 발판에서 걸어 내려가도 다시 눌러야 발사.
  - 연료는 착지한 스텝에 바로 전량 충전.
- 총알 시작 가설 🧪 (Downwell 기본 총에서 측정, 타일 크기가 같아 환산 없음):
  - 아래로 480px/s, 0.2초 (12스텝, 96px) 날아간 뒤 다음 스텝에 사라짐. 고체에 닿으면 바로 사라짐.
  - 크기 4×8px.
  - Downwell은 사거리 끝에서 감속하며 사라지고 속도에 무작위 편차가 있음. M1은 단순화해서 생략.

### 5.2 밟기와 적 ✅

- 위에서 밟으면 다음이 한 번에 일어남:
  - 처치 + 연료 전량 충전 + 콤보 +1
  - **점프보다 높은 바운스**
- 바운스 가설 🧪: Celeste 퍼퍼(Puffer) 밟기처럼 위쪽 속도를 0.2초 동안 유지.
  - M1 구현 (2026-10-10): 밟은 다음 0.2초(12스텝)의 이동을 위쪽 280px/s (Celeste 140의 2배)로, 버튼과 상관없이 유지. 끝까지 오르면 점프보다 높음 (테스트로 확인). 밟으면 코요테 시간과 점프 유지도 끝남.
  - 판정: 이번 스텝 이동 전에 발이 적의 윗면 이상에 있었고, 이동 후 겹치면 밟기. 그 밖의 접촉은 피격.
  - 밟으면 발을 적의 윗면에 맞춘 뒤 튕김 ✅ (2026-10-11). 같은 적을 밟으면 낙하 거리와 상관없이 항상 같은 높이로 오름 (Celeste `Player.Bounce`와 같은 방식).
  - 동시 접촉 ✅ (2026-10-10 확정): 한 스텝에 위에서 밟은 적은 모두 처치하고, 밟기가 있었던 스텝에는 피격하지 않음. 안전한 윗면은 옆의 위험한 적에 살짝 걸쳐도 안전하게. 피격은 가장 가까이 겹친 적 반대쪽으로 넉백. 적 저장 순서와 무관하게 결과가 같음.

**적 3분류**: 위험한 면은 가시 모양 + 색으로 일관되게 표시

| 분류 | 처치 방법 | 예시 역할 |
|---|---|---|
| 위가 안전 | 밟기 | 기본 발판 역할 적 |
| 아래가 안전 | 드릴 헬멧으로 들이받기 | 머리 위를 막는 적 |
| 전부 위험 | 쏘기만 가능 | 추월한 뒤 아래로 쏴서 처리 |

- **퍼퍼형 적**: 옆이나 아래에서 닿으면 피해 대신 옆으로 튕겨 보냄. 피하는 동작이 곧 이동 수단이 됨.
- M1의 적 2종 ✅ (2026-10-10): "위가 안전"(밟기)과 "전부 위험"(쏘기만 가능). 아래로 쏘기가 추진이자 공격인 핵심 루프를 시험하기 위함. "아래가 안전"과 퍼퍼형은 M2.

**피격과 HP** ✅ (M1 범위, 2026-10-10)
- HP 4 🧪 (Downwell 값). 적이나 물에 닿으면 HP -1 + 연료 전량 충전 + 넉백 + 짧은 무적.
- HP가 0이 되면 판이 끝나고 R로 재시작.
- 콤보 보상, 젬, HP 회복은 M2.
- M1 구현 수치 🧪 (2026-10-10, [data/tuning.json](../data/tuning.json)의 `player`):
  - 무적 1.5초 (Downwell 90프레임). 무적 중에는 적을 통과하고, 밟기는 됨. 플레이어가 깜빡임.
  - 넉백 (2026-10-11, Downwell 측정값으로 교체): 위로 190px/s, 좌우로는 적 중심 → 플레이어 중심 방향의 가로 성분 × 180px/s (옆에서 맞을수록 세고, 바로 위아래에서 맞으면 좌우 속도 유지).
    - Downwell은 거의 모든 적이 같은 넉백(좌우 3px/f × 방향 가로 성분, 위 2px/f)을 씀 ([references.md](references.md#플레이어)).
    - 좌우 3px/f = 180px/s는 그대로 사용. 위 2px/f(120px/s)는 Downwell 중력에서 약 10px 뜨는 값이라, 우리 중력(1800)에서 같은 10px이 되도록 190px/s로 환산.
    - 좌우 넉백 최대값이 달리기 최대 속도(180)와 같아서, Celeste의 최대 속도 초과 감속(RunReduce)은 아직 필요 없음.
  - 재시작: 탑 모드는 새 탑 (`-seed`를 주면 같은 탑), 조각 모드는 같은 조각.

**M1의 적 2종** 🧪 (2026-10-10, [data/tuning.json](../data/tuning.json)의 `enemies`, 이름은 임시)

| 이름 | 분류 | 크기 | 총알 HP | 움직임 |
|---|---|---|---|---|
| Floater | 위가 안전 (밟기) | 14×12 | 2 | 좌우로 30px/s, 벽에서 방향 전환 |
| Spiker | 전부 위험 (쏘기만) | 14×14 | 3 | 제자리 |

- 회색 박스에서는 위험한 면을 빨간 테두리로 표시함 (Floater는 윗면만 빨갛지 않음).
- 적 정의는 판이 시작될 때 적용됨. 실행 중 수치를 바꾸면 다음 판(R)부터 반영.
- 적은 LDtk `Entities` 레이어에 엔티티로 배치함 (7장 조각 작성 규칙). 적이 벽 안에 생기면 판 시작이 오류로 거부됨.
- 총알은 한 스텝에 지나간 경로 전체로 적을 판정하고, 가장 먼저 만나는(가장 위의) 적이 맞음. 총알이 빨라도 적을 건너뛰지 않음.

### 5.3 콤보 ✅

- 발판에 착지하면 종료. 피격으로는 끊기지 않음.
- 보상 단계는 Downwell(8/15/25)을 참고하되 수치와 보상은 새로 설계 🧪.
  - 후보: 젬, 최대 연료 +1, HP 조각, 수위 하강

### 5.4 물 (차오르는 위협) ✅

Celeste RisingLava의 따라잡기(고무줄) 로직을 사용하되, 고무줄을 더 짧게 당겨 물이 항상 화면 아래 끝 근처에 보이게 합니다 ✅ (2026-10-11 변경, 디자인 원칙 4 "목표가 한눈에 보임"). 수치는 [data/tuning.json](../data/tuning.json)의 `water` 🧪.

- 기준선: 카메라 아래 끝에서 24px 위 (Celeste 12의 2배)
- 화면 밖으로 처지면 빠르게(최대 3배) 따라와 화면에 보이게 되고, 기준선에서 48px(화면 아래 끝에서 24px 아래)보다 더 처지지 않음.
  - 처음에는 Celeste 환산값(최대 2배, 192px까지 처짐)이었음. 그러면 빨리 오르는 플레이어에게 물이 화면 밖에 머물러 안 보임.
- 화면 안으로 올라오면 64px 구간에 걸쳐 속도가 최대 0.5배까지 내려감.
- 그래서 물은 늘 보이지만, 잘하는 플레이어에게는 느리고 머뭇거리는 플레이어만 압박을 받음.
- 판이 시작되고 첫 점프(버튼 입력) 전까지 물은 오르지 않음 ✅ (2026-10-11). Celeste 용암도 재시작 직후 플레이어가 움직일 때까지 기다림 (`RisingLava.cs:69-83, 128-138`).
- 기본 속도: M1은 30px/s 🧪. Celeste 환산값 60px/s는 "마지막 구역에서나 맞을 속도"라는 플레이 소감(2026-10-11)에 따라 절반으로 낮춤. 구역·층별 속도 곡선은 M2에서 정함.
- M1 구현 (2026-10-11):
  - 물은 Celeste처럼 맵 바닥 아래(32px, Celeste 16의 2배)에서 시작.
  - 물은 탑 모드에만 있음. 조각 하나만 쓰는 `-chunk` 모드는 시험용이라 물이 없음.

**추락 안전망** ✅ (Celeste 어시스트 모드의 무적 용암 처리 + HP)

물에 닿으면:
- HP -1
- 연료 전량 충전
- 위로 크게 튕겨 냄
- 물이 닿은 순간부터 0.5초 동안 멈추고, 그 안에서 0.4초에 걸쳐 96px 내려감 (처음엔 빠르고 끝에서 느린 곡선)
  - ✅ 2026-10-11 확정 (문구 정정): 처음엔 "0.4초 동안 내려간 뒤 0.5초 멈춤"(합 0.9초)으로 적었으나, Celeste 코드(`RisingLava.cs:95-112`)대로 멈춤 0.5초 안에 후퇴 0.4초가 들어 있는 방식으로 정함.
  - 멈춤은 후퇴보다 짧을 수 없음 (설정 검증).
- 짧은 무적 시간
- M1 구현 (2026-10-11):
  - 튕김: 위쪽 400px/s 한 번 (Celeste -200의 2배). 무적은 적 피격과 같은 1.5초.
  - 멈춘 동안에는 다시 잡히지 않음. 무적 중에 물에 닿으면 HP는 잃지 않고 튕김과 후퇴만 일어남.
  - 후퇴(96px)는 최대 처짐(48px)보다 길어서, 멈춘 동안에는 최대 처짐 제한을 걸지 않음. 멈춤이 끝나면 물은 화면 아래 끝 바로 밑(화면 밖)으로 당겨진 뒤 다시 오름.
  - 마지막 HP를 물에서 잃으면 판이 끝남.

### 5.5 지형 ✅

| 블록 | 동작 |
|---|---|
| 단방향 발판 | 아래에서 통과, 위에 착지 |
| 드릴 블록 | 드릴 헬멧으로 속도와 상관없이 파괴. 깰 때 0.05초 멈춤 + 작은 위쪽 튕김 |
| 파괴 불가 블록 | 경로 설계용 |

**깨지는 블록의 종류** ✅ (2026-10-10)
- 블록마다 "드릴로 깨짐", "총알로 깨짐" 두 속성을 데이터로 정의. 새 종류는 데이터와 조각 값만 추가하면 됨.
- 드릴은 머리 위 블록을, 총알(아래로만 나감)은 발 아래 블록을 깸. 그래서 총알로 깨지는 블록은 "내 사격이 딛고 설 발판을 부순다"는 긴장을 만듦.
- M1 회색 박스에는 아래 4종을 모두 넣고, 플레이테스트 후 남길 종류를 정함 🎮. 종류마다 색을 달리해 한눈에 구분되게 함.

| 블록 | 드릴 (아래에서) | 총알 (위에서) | 쓰임새 |
|---|---|---|---|
| 드릴 블록 | 깨짐 | 안 깨짐 | 머리로 뚫는 길. 발판으로는 안전 |
| 무른 블록 | 깨짐 | 깨짐 | 뚫고 갈 수 있지만, 쏘다 보면 내려앉을 발판도 사라짐 |
| 총알 전용 블록 | 안 깨짐 | 깨짐 | 아래에서는 돌아가야 하는 벽, 위에서 쏘면 사라지는 발판 |
| 파괴 불가 블록 | 안 깨짐 | 안 깨짐 | 경로 설계용 |

필수 보정 (Celeste 방식):
- 천장 모서리에 머리를 부딪히면 옆으로 1~4px 밀어서 통과시켜 줌
- 단방향 발판을 통과하는 중이면 위로 밀어 주는 보조 속도

**M1 구현 내용** (2026-10-10):
- 블록 정의는 [data/tuning.json](../data/tuning.json)의 `blocks`: 값, 이름, 단방향 여부, 드릴로 깨짐, 총알로 깨짐, 회색 박스 색.
- 단방향 발판은 윗면 선만 막음. 위로 오르는 중에는 착지로 치지 않음 (Celeste와 같음). 그래서 연사로 발판을 통과해도 연료가 충전되거나 연사가 끊기지 않음.
- 드릴은 위로 오르다 머리가 닿은 블록만 깸. 머리 위에 걸친 칸이 모두 대상이고 옆은 깨지 않음.
- 총알은 단방향 발판을 통과함 🧪 (발판 아래 적을 쏠 수 있게). 발밑에서 생기자마자 블록에 겹치면 그 블록을 바로 깸.
- 깰 때의 0.05초 멈춤은 6장 연출에서 구현 (2026-10-11).
- 가설 수치 🧪:

| 항목 | 값 | 근거 |
|---|---|---|
| 단방향 발판 통과 보조 | 위로 80px/s | Celeste 40px/s의 2배 |
| 천장 모서리 보정 | 최대 4px. 좌우로 움직이는 중이면 그 방향으로만, 멈춰 있으면 왼쪽 먼저 양쪽 시도 | Celeste 값 그대로 |
| 드릴 튕김 | `vy = min(vy, -240)` 한 번 (발사 한 발과 같은 크기) | Celeste는 대시 블록을 깨면 -120px/s를 0.15초 유지. 2배로 환산하면 점프보다 커서 "작은 튕김"에 맞게 줄임 |

### 5.6 무기와 슈트 ✅ (두 층 구조)

**무기**: 영구적이고 교체식. 반동 = 추진 방식. 목록은 후보 🔶

| 무기 | 추진 특성 | 전투 특성 |
|---|---|---|
| 리벳건 (기본) | 연사, 꾸준히 떠오르는 호버 | 단발, 빠른 연사 |
| 블런더버스 | 한 방에 크게 상승 (사실상 더블 점프) | 근거리 산탄 |
| 증기 캐논 | 누르고 있다 떼면 모은 만큼 수직 발사 | 관통 |
| 펌프건 | 수면 가까이에서 추진력 증가 | 물줄기 |

- 무기를 바꿀 때 HP +1 또는 최대 연료 +2 중 하나를 받는 맞교환 (Downwell 구조 유지).

**슈트**: 일시적이며 맞으면 대신 부서지는 1회 방패 (Jetpack Joyride 탈것 방식). 목록은 후보 🔶

- 버튼 하나가 하는 일 자체를 바꿈.
- 지속 시간이 끝나기 0.5초 전부터 깜빡이며 경고 (Celeste 깃털 방식).

| 슈트 | 버튼 동작 |
|---|---|
| 날개 슈트 | 누를 때마다 날갯짓 |
| 중력 반전 슈트 | 위로 "떨어짐" (Downwell에 대한 오마주) |
| 스프링 부츠 | 누르는 시간만큼 모았다가 점프 |

### 5.7 업그레이드 ✅ (방향), 🔶 (목록)

Downwell은 23종, 전부 1회 획득, 균등 확률 추첨, 조합 효과 로직 없음. 우리는 이렇게 차별화합니다.

- 테마 동사(추진, 드릴, 물, 구조, 밟기)에 묶기
- 맞교환형 업그레이드 포함
- 같은 태그 3개를 모으면 세트 효과

| 후보 | 효과 |

| 부력 조끼 | 층마다 1회, 물에 빠져도 피해 없이 튕겨 나옴 |
| 역류 밸브 | 일정 콤보를 달성하면 수위 하강 |
| 무거운 갑주 | 최대 HP +2, 중력 +15% |
| 스프링 무릎 | 밟기 바운스 +30%, 대신 발판 착지로는 연료 충전 안 됨 |
| 낙하 축전 | 떨어진 거리만큼 다음 추진 1발 강화 |

### 5.8 탑 구조: 갈림길, 격벽실, 구조 NPC, 밸브 ✅

**갈림길** (Hades의 문 아이콘에서 착안)
- 통로가 2갈래로 갈라지고, 각 끝의 보상 아이콘이 위로 미리 보임.
- 위험한 쪽일수록 보상이 좋음.

**격벽실** (Downwell의 시간 정지 방을 대체)
- 들어가면 문이 닫히고 물이 멈춤.
- 구조한 NPC가 여기서 상점이나 대장장이 역할을 함.

**구조 NPC**
- 물에 갇힌 탑 주민. 우회해서 구하면 그 판의 다음 격벽실에 등장함.
- 판이 끝나면 초기화.

**배수 밸브**
- 갈림길 보상 중 하나. 드릴로 부수면 물을 화면 밖으로 크게 밀어내고 몇 초간 멈춤.
- 즉 시간을 버는 장치. 고무줄 로직 때문에 물은 이후 다시 따라옴.

### 5.9 메타 진행 🔶

**판마다 초기화 + 수평 해금** (Downwell 방식)
- 강해지는 영구 성장은 없음.
- 누적 기록(구조한 NPC 수, 도달 높이, 젬 등)으로 새 무기, 슈트, 업그레이드를 **추첨 대상에 추가**.
- 시작 스타일과 팔레트도 해금 대상.
- 저장 데이터는 해금 플래그와 누적 카운터뿐.

## 6. 카메라, 물리, 연출 (Celeste 기준) ✅

**단위**: 초 단위 상수 + 60Hz 고정 업데이트. 위치는 정수 픽셀로 두고 소수점 이하는 따로 누적.

**물리 시작값 🧪**
- 화면에 보이는 세로 타일 수가 Celeste와 같음 (22.5타일). 그래서 8px 타일 기준인 Celeste 값을 16px 타일에 맞게 2배로 환산.
- 현재 값은 [data/tuning.json](../data/tuning.json)에 있음. 아래 표와 함께 고칠 것.
- 물리 동작:

| 항목 | 값 |
|---|---|
| 중력 | 1800px/s² |
| 최대 낙하 속도 | 320px/s |
| 점프 | -210px/s를 버튼을 누르는 동안 최대 0.2초 (발사 프레임 포함 12스텝) 유지 (가변 점프). 끝까지 누르면 53px (약 3.3타일, 꼭대기 중력 절반 포함) |
| 꼭대기 중력 절반 | 세로 속도 절댓값 80 미만이고 버튼을 누르고 있을 때 중력 × 0.5. 발사 중에도 같은 조건이면 적용 ✅ (2026-10-10, Celeste와 같은 방식) |
| 좌우 최대 속도 / 가속 | 180px/s / 2000px/s² (2026-10-10 추가, Celeste 값 2배) |
| 공중 가속 배율 | 0.65 (2026-10-10 추가, Celeste 값) |
| 판정 박스 | 12×20px (임시. 캐릭터 약 20px 기준, M1 끝에 🎮 결정) |

- 입력 관대함:

| 항목 | 값 |
|---|---|
| 코요테 타임 (발판에서 떨어진 뒤에도 점프 허용) | 0.1초 (떨어진 뒤 공중 6스텝째까지) |
| 입력 버퍼 (버튼 입력 기억) | 0.08초 (누른 스텝부터 5스텝 안에 점프가 시작돼야 함. 착지 전에 뗀 입력은 짧은 점프) |

**카메라**
- 가로는 고정. 세로는 위로만 움직임.
- 플레이어를 화면 아래쪽 약 1/3에 둠.
- 위로 움직일 때 속도 × 0.2만큼 앞을 미리 보여 줌 (Celeste 깃털 상태 방식).
- 따라가는 공식: `cam += (target - cam) * (1 - 0.01^dt)`
- M1 구현 (2026-10-10): 카메라는 시뮬레이션에 있음 (물이 화면 아래 끝을 기준으로 움직이므로). 맵 밖으로는 나가지 않음. 수치는 [data/tuning.json](../data/tuning.json)의 `camera` 🧪 (위치 0.667, 미리 보기 0.2초, 1초 뒤 남는 거리 1%).
- 카메라가 내려가지 않으므로, 발판을 놓쳐 떨어지면 플레이어가 화면 아래로 사라질 수 있음. 물과 추락 안전망(5.4)이 이 상황을 받아 줌.

**연출**

| 이벤트 | 연출 |
|---|---|
| 밟기, 총알 명중 | 1프레임 멈춤 ✅ (2026-10-11, Downwell처럼 맞히고 처치할 때마다 짧게) |
| 드릴 | 0.05초 멈춤 (Celeste 블록 파괴와 같음). 착지 충전은 멈추지 않고 램프 번쩍임만 (아래 M1 구현 참고) |
| 밟기 | 화면 흔들림 ✅ (2026-10-11, Downwell처럼 밟을 때마다). 0.16초, 시작 2px 🧪 |
| 밟기, 물에서 튕겨 나옴 | 점프와 같은 늘어남 (0.6, 1.4) ✅ (2026-10-11, Celeste `Bounce`와 같음) |
| 드릴 파괴 | 파편 + 화면 흔들림(0.2초, 시작 3px 🧪) + 늘어남 ✅ (2026-10-11). Celeste는 블록을 깰 때 파편을 바깥으로 튕겨 내고 소리를 내서, 멈춘 0.05초가 "부서지는 순간"으로 보임 |
| 총알로 블록 파괴 | 파편 (아래로 튐) ✅ (2026-10-11) |
| 큰 발사 (스프링, 슈트) | 0.1초 멈춤 + 잔상 |
| 발사 | 발사 방향으로 화면 흔들림 0.2초 |
| 점프 / 착지 | 늘어남·찌그러짐 (0.6, 1.4) / 최대 (1.6, 0.4) |
| 남은 연료 | 제트팩 불꽃이나 헬멧 램프 색으로 표시, 충전 시 흰색 번쩍 (Celeste 머리카락 색 방식) |

**M1 구현** (2026-10-11, 수치는 [data/tuning.json](../data/tuning.json)의 `feel` 🧪):
- 멈춤은 시뮬레이션에서 처리 (게임 전체가 멈추고 리플레이로 재현됨). 멈춘 동안 누른 버튼은, 멈춤이 끝날 때까지 누르고 있으면 그다음 스텝에 인식됨. 멈춘 동안 눌렀다 떼면 놓침.
- ✅ (2026-10-11 확정, 같은 날 아래처럼 세분) 멈춤은 **밟기와 드릴 파괴에만** 걸고, 착지 충전에는 걸지 않음. 우리 게임은 착지할 때마다 충전되어 매번 멈추면 흐름이 끊기기 때문. Celeste의 "충전 0.05초"는 충전 크리스털을 먹을 때이고, 우리 게임에서 그에 해당하는 동작은 밟기(처치 + 충전). 착지 충전은 램프의 흰색 번쩍임으로만 표시.
- ✅ (2026-10-11 결정) 멈춤 길이를 원인별로 나눔: 밟기와 총알 명중은 1프레임(`feel.stompFreeze`, `feel.hitFreeze`), 드릴 파괴는 0.05초(`feel.drillFreeze`). 한 스텝에 겹치면 가장 긴 것 하나.
  - Downwell은 총알이 적에 맞을 때와 적이 죽을 때(밟아서 죽여도) 게임을 1스텝 동안 절반 속도로 돌려 약 1프레임 멈칫하게 함. 블록 파괴에는 없음.
  - Celeste는 충전 크리스털과 블록 파괴에 0.05초 완전 멈춤을 쓰고, 퍼퍼를 밟을 때는 멈추지 않음.
  - 밟기 연쇄가 핵심이라 밟기는 Downwell처럼 짧게, 드릴은 Celeste처럼 길게.
- 파편 (2026-10-11): 깨진 칸마다 블록 색 4×4px 조각 2×2개 (한 스텝에 최대 8칸, 드릴로 깬 칸 먼저. 그 이상은 블록만 깨지고 파편은 생략). 처음엔 2px씩 벌어진 채 칸 안에 생겨, 멈춘 동안 금 간 블록으로 보임. 드릴은 위·옆으로, 총알은 아래·옆으로 튀고 중력으로 떨어지다 0.5초 뒤 사라짐. 수치는 `feel.debris*` 🧪. 소리는 M3 오디오 작업에서.
- 큰 발사(스프링, 슈트)는 M1에 없어서 구현하지 않음.
- 화면 흔들림·늘어남·찌그러짐·램프는 그리기에서만 처리 (시뮬레이션 카메라와 판정에는 영향 없음). 시뮬레이션 이벤트로만 바뀌어 리플레이에서 같은 화면이 나옴.
  - 흔들림: 발사마다 0.2초. 0.04초마다 방향이 번갈아 바뀌고 크기는 남은 시간 × 20px (올림, Celeste 10의 2배). 발사가 아래 방향이라 세로로 흔들림.
  - 늘어남·찌그러짐: 점프 (0.6, 1.4). 착지는 낙하 속도 480px/s(Celeste 240의 2배)에서 최대 (1.6, 0.4), 그보다 느리면 비례해서 덜함. 초당 1.75씩 원래 크기로 돌아옴. 판정 박스 크기는 그대로.
  - 헬멧 램프: 플레이어 위 4px. 연료가 가득이면 주황(`#ff9a3c`), 줄수록 파랑(`#3c78ff`) 쪽으로 섞임. 연료가 늘면 0.12초(7스텝) 흰색.

## 7. 화면과 레벨 생성

**논리 해상도 🔶: 208×360** (16px 타일, 가로 13칸 = 안쪽 11칸 + 양쪽 벽)
- 맵 모양과 보이는 범위가 모든 기기에서 같도록 폭과 높이를 모두 고정.
- 이 게임은 위가 더 많이 보이면 유리하기 때문에 높이도 고정해야 공정함.
- 플랫폼별 배치:
  - PC 1080p: 3배 (624×1080)를 가운데 배치하고, 양옆은 HUD와 아트 영역. 720p, 1440p, 4K는 각각 2배, 4배, 6배로 정수 배율.
  - 모바일 (가로 1080): 5배 (1040×1800). 남는 세로 공간은 위쪽 HUD와 아래쪽 터치 버튼.

**좁아 보이는 문제**는 화면 폭이 아니라 안쪽 지형으로 해결: 좁은 통로, 넓은 홀, 갈림길 조각.

**레벨 생성**
- 손으로 만든 조각(청크)을 이어 붙임 (Downwell 방식).
- 조각은 좌우 반전 허용, 같은 조각 연속 금지.
- M1 탑 쌓기 (2026-10-10, M2 조각 생성기 전까지의 임시 방식): 시작 조각(`tower.base`) 위에 조각 목록(`tower.pool`)에서 무작위로 골라 `tower.length`개까지 쌓음 🧪. 시드가 같으면 같은 탑이 나옴 (`internal/rng`, SplitMix64).
  - 쌓이는 조각은 맨 아래 줄과 맨 위 줄이 막혀 있으면 안 됨. 도달 가능성 검증 도구(M2)가 생기기 전까지는 직접 확인. 그래서 바닥이 있는 시험용 조각 `Blocks`는 목록에서 뺌.
  - 실행: `go run ./cmd/uplunge` (새 탑, 시드를 로그에 출력), `-seed N` (같은 탑 다시), `-chunk Name` (조각 하나만), `-lab` (비율 실험 통로).
  - 탑 꼭대기(맵 맨 위)에 닿으면 판 클리어. 걸린 시간과 남은 HP를 보여 주고 R로 다음 판 ✅ (2026-10-11). 조각 하나만 쓰는 모드는 위에서 시작하므로 클리어가 없음.
  - 꼭대기에는 체크무늬 결승선(높이 8px)을 그림 ✅ (2026-10-11). 머리가 맵 맨 위에 닿으면 클리어.
  - M1 플레이테스트 탑 (2026-10-11): 시작 조각 `Start`를 포함해 조각 24개 (`tower.length`, Start + 23) 🧪, 1~2분 분량 목표 ✅. 조각 목록은 Shaft, Ladder와 플레이테스트 조각 7개 (Steps, Zigzag, DrillGate, Floaters, SpikerHall, SoftFloor, Chimney).
  - M2 검증 도구 전까지의 최소 안전장치: 탑 조각 목록의 모든 줄에 위로 지나갈 수 있는 칸(빈칸, 단방향 발판, 드릴로 깨지는 블록)이 있어야 함. `go test ./internal/sim/`이 검사함.

**비율 실험 통로** ✅ (2026-10-11, `-lab`)
- 4장의 핵심 튜닝 비율(닿는 높이 ÷ 적 사이 평균 세로 간격)을 직접 찾기 위한 M1 도구.
- 벽만 있는 통로(`lab.rows` 줄)에 `lab.enemy`를 `lab.spacing`px마다, 위아래로 최대 `lab.jitter`px 흔들어 무작위 가로 위치에 배치. 물과 클리어는 탑과 같음.
- 화면에 현재 비율을 바닥 출발과 밟은 뒤 출발 두 가지로 표시: 닿는 높이는 현재 수치로 계산(`sim.GroundReach`, `sim.StompReach`), 적 간격은 그 판에 놓인 밟을 수 있는 적의 평균 세로 간격(`sim.EnemyGap`). 일반 탑에서도 같은 식으로 표시.
- 실험 모드에서는 판이 끝나지 않아도 R로 바로 다시 시작함 (수치를 바꿔 가며 비교하기 위한 개발 도구라서). 탑 모드는 판이 끝나거나 클리어한 뒤에만.
- 절차는 [playtest-m1.md](playtest-m1.md).
- Downwell은 경로 검증 코드가 없음 (어디서든 떨어지면 내려가니까). 상승형은 **도달 가능성 검증이 필수** ✅.
  - 규칙: "연료가 0이어도 점프 높이 안에 발판이 있다" 또는 "연료원이 보장된다".
- Downwell은 조각 안에도 확률 칸(예: 50% 벽, 25% 상자)을 둬서 같은 조각도 매번 조금씩 달라짐 ([references.md](references.md#레벨과-카메라)). 조각 수를 줄이는 수단으로 M2 조각 생성기에서 검토 🔶.

**조각 제작 분담** ✅ (2026-10-10)
- M1: Claude가 회색 박스 조각을 만들고 로더 테스트와 스크린샷으로 검증.
- M2 이후: Claude가 초안 조각을 만들고, 도달 가능성 검증 도구가 오를 수 없는 조각을 걸러 냄. 개발자는 플레이해 보고 고치거나 빼는 큐레이션을 맡음.

**조각 작성 규칙** ✅ (2026-10-10 확정, M2에서 조각 생성기를 만들 때 다시 검토)
- LDtk 프로젝트 하나([assets/chunks/chunks.ldtk](../assets/chunks/chunks.ldtk))에 레벨 하나 = 조각 하나.
- 충돌은 IntGrid 레이어 `Collision`: 0 = 빈칸, 1 = solid, 2 = one_way, 3 = drill, 4 = soft, 5 = bullet_only (2026-10-10 추가).
  - 0이 아닌 값은 모두 [data/tuning.json](../data/tuning.json)의 `blocks`에 정의되어 있어야 하고, LDtk의 값 이름(identifier)은 블록 이름과 같아야 함. `go test ./internal/sim/`이 검사함.
  - 새 블록 종류는 `blocks`에 한 줄, LDtk `Collision` 레이어에 값 하나를 추가하면 됨.
- 적은 선택 레이어 `Entities`에 엔티티로 놓음 (2026-10-10 추가). 엔티티 이름은 [data/tuning.json](../data/tuning.json)의 `enemies` 이름과 같아야 하고, 적은 엔티티 사각형의 가운데에 생김. `go test ./internal/sim/`이 검사함.
  - 탑에 쌓을 때 조각이 좌우 반전되면 적 위치도 함께 반전됨.
- 조각 폭은 양쪽 벽을 포함해 13칸 (16px 타일), 높이는 자유.
- 레벨을 별도 파일로 저장하는 옵션(Save levels to separate files), 여러 월드(Multi-worlds), `Collision` 레이어의 픽셀 오프셋은 쓰지 않음. 로더가 오류로 거부함.

## 8. 아트 디렉션 (초안) 🔶

참고작 Shelldiver에서 **원칙만** 가져옵니다. 에셋, 캐릭터, 형태를 모방하지 않습니다.

- **크기**: 16px 타일. 캐릭터는 약 20px, 머리(드릴 헬멧)가 큰 2등신.
- **외곽선**: 두꺼운 1px 어두운 외곽선으로 실루엣을 확보.
- **색 구조**: 구역마다 한 색상 계열로 거의 단색 환경 + 캐릭터, 적, 아이템은 채도 높은 대비색.
- **지형**: 어두운 내부 덩어리 + 위쪽 테두리에 밝은 테두리(이끼, 녹, 물때). 계단식 블록 실루엣.
- **배경**: 2~3겹의 시차 스크롤(패럴랙스) 레이어. 멀수록 밝고 채도가 낮음.
- **물**: 모든 구역에서 쓰지 않는 **물 전용 색 1개**를 예약. 밝은 수면선을 그리고, 물에 잠겼을 때는 화면 왜곡 셰이더.
- **효과**: 물방울, 거품, 반짝임, 부드러운 발광. 물결과 흔들림은 셰이더로.
- **진행감**: 위로 갈수록 밝아짐.
  - 어두운 지하 저수조 → 하인 구역 → 서고 → 꼭대기 공주의 방(따뜻한 빛)
- 확정되면 별도의 `art-style.md`(팔레트 hex 값, 외곽선·명암 규칙, 크기표)로 분리.

## 9. 기술

### 9.1 엔진 ✅: Ebitengine (Go) — 2026-10-10 확정

선정 기준은 Claude가 코드를 작성하고 스스로 검증하기 좋은지 여부입니다.

- **프로젝트 전체가 코드와 텍스트**: 에디터 전용 연결 작업이나 바이너리 씬 파일이 없음.
- **Go**: gofmt로 스타일이 하나로 고정되고, 언어가 작고, 정적 타입. 컴파일이 빨라서 수정 → 확인 반복이 짧음.
- **API 안정성**: v2 API가 안정적이라 학습 데이터와 실제 API가 어긋날 위험이 낮음.
- **플랫폼**:
  - Steam: go-steamworks
  - 모바일: ebitenmobile
  - Nintendo Switch: 공식 지원. 단, 닌텐도 개발자 계약과 비공개 툴체인이 필요.
- **단점**: 에디터가 없음. 레벨은 LDtk, 스프라이트는 Aseprite로 보완. UI와 파티클은 직접 구현.
- **대안**:
  - MonoGame/FNA (C#, Celeste가 쓴 스택): 콘솔 포팅 경로가 가장 넓음.
  - Godot 4: 에디터가 필요할 때.

### 9.2 테스트 전략 🔶

1. 게임 로직(물리, 충돌, 생성기)은 렌더링과 분리된 순수 Go 패키지로 작성 → `go test`
2. **입력 리플레이 테스트**: 프레임별 입력을 기록하고 재생해서 결과 위치나 상태를 정해 둔 정답과 비교
3. **조각 도달성 검증**: 모든 LDtk 조각을 `go test`로 자동 검사
4. **스크린샷 자동화**: 디버그 실행 옵션으로 지정한 프레임 PNG를 저장하고 자동 종료 → Claude가 이미지를 직접 확인

### 9.3 에셋 파이프라인 🔶

```
콘셉트 아트 (AI 이미지 생성, Codex CLI)
  → 픽셀 정규화 스크립트 (결정적 도구: 격자 맞춤, 팔레트 양자화, 외곽선 규칙)
  → Aseprite 정리 (Claude가 Lua 스크립트로 수정하고, 사람이 검수)
  → Aseprite CLI 내보내기 (스프라이트 시트 PNG + JSON. 애니메이션 이름은 태그, 판정 박스는 슬라이스)
  → 게임 임포트
```

- 정규화는 LLM이 아니라 **스크립트**로: 같은 입력이면 같은 결과가 나와야 조정할 수 있음.
- **캐릭터 애니메이션**:
  - 파츠(헬멧, 몸통, 팔, 다리, 제트팩)를 레이어로 분리하고, 레이어 위치를 옮겨 프레임을 만들어 일관성 확보.
  - 늘어남·찌그러짐, 흔들림, 불꽃 같은 움직임은 코드로 처리.
- 3D 모델을 픽셀로 렌더링하는 방식은 채택하지 않음. 이 정도 캐릭터 크기에서는 뭉개지고, 파이프라인 비용이 큼.
- Steam 출시 시 AI 생성 콘텐츠 사용 여부를 공개해야 함.
